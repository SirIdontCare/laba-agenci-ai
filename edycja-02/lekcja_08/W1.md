# L08 · W1 — Poczta: pięć wiadomości, kolejka pracy i zero wysyłek

**CORE: 15 min. Efekt:** lista szkiców z priorytetem i dowodami. Wymagane: kontrakt L02, źródła L06, Auth L07.

## Zbuduj

1. Załaduj pięć development maili z `data/fixtures.json`. To import fikcyjnych wiadomości, nie połączenie Gmail. UI wyraźnie oznacza dane DEMO.
2. Uruchom istniejący schemat triage dla każdej wiadomości. Wiadomości o płatności bez integracji płatniczej trafiają do kontroli. Pytanie o cenę korzysta z aktywnej wiedzy, nie z modelowej pamięci.
3. Pokaż kolejkę: kategoria, priorytet, missing_data, źródło, szkic i status. Priorytet wynika z jawnej reguły procesu, nie stylu, uprzejmości czy „profesjonalnego języka” nadawcy.
4. Rekord szkicu zapisuje właściciela i ID wejściowej wiadomości. Ponowne przeliczenie to nowa wersja szkicu, nie drugi wysłany mail. Przycisk „Kopiuj szkic” nie nazywa się „Wysłano”.
5. Przetestuj injection w treści maila i mail z niejasną prośbą. Żadne z nich nie może zmienić uprawnień ani samodzielnie wywołać zewnętrznego skutku.

## Polecenie do asystenta

```text
Dodaj preset email_triage do istniejącego silnika. Import pięciu fikcyjnych maili, schema z L02, źródła z L06, owner z sesji. Wynik to kolejka szkiców; bez Gmail OAuth i bez sendEmail. Braki oraz potrzeba kontroli mają być widoczne. Nie ujawniaj expected modelowi.
```

## Odbiór

Pięć maili ma wynik albo jawny błąd; szkice mają właściciela; nie potwierdzono płatności bez danych; nie wysłano wiadomości; ponowienie nie tworzy niekontrolowanych skutków.

**Ratunek:** pojedynczy mail, potem seria sekwencyjna. **STRETCH:** ręczny pomiar czasu procesu z korektami versus gotowe AI; nie licz wyłącznie generacji jako całej oszczędności.
