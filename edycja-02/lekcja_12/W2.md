# L12 · W2 — Jedna poprawka i pełny cykl

**CORE: 20 min w planie finału. Efekt:** działająca poprawka z dowodem przed/po.

## Zrób

1. Wybierz jeden błąd z feedbacku partnera o dużym wpływie i małym zakresie. Zapisz input i krok odtworzenia. Nie naprawiaj pięciu rzeczy jednocześnie.
2. Odtwórz go na obecnym commicie. Zrób test, który wykrywa problem. Jeżeli nie potrafisz go odtworzyć, zaznacz to i wybierz lepiej opisany przypadek.
3. Asystent proponuje najmniejszą zmianę. Sprawdź diff: bez zamiany OpenRouter na inny dostawca, bez wyłączania RLS, bez usuwania testu, żeby był zielony.
4. Uruchom test regresji oraz kluczowy poprawny scenariusz. Następnie build, commit i deploy. Sprawdź wdrożony URL — lokalny sukces nie jest testem hostingu.
5. Partner powtarza dokładnie ten sam input. Zapisz wynik i hash commita. Gdy wdrożenie nie jest gotowe, oznacz NOT RUN zamiast wpisywać pełny sukces.

## Polecenie do asystenta

```text
Oto odtwarzalny błąd z feedbacku: [opis]. Najpierw potwierdź go testem. Zaproponuj najmniejszy diff, napraw bez zmiany architektury i bez usuwania zabezpieczeń. Uruchom regresję oraz normalny przypadek. Pokaż wyniki, build i instrukcję weryfikacji po deployu. Nie podawaj PASS dla nieuruchomionych etapów.
```

## Odbiór

Input jest identyczny przed/po; stary błąd nie występuje; normalne zadanie działa; nowa wersja jest identyfikowalna; partner rozumie zmianę. Nie ma globalnego „napraw wszystko”.

**Ratunek:** popraw komunikat lub flow, jeśli błąd backendu wymaga większej pracy; większą lukę zapisz jako blokadę pilotażu. **STRETCH:** automatyczny test w CI przed każdym kolejnym deployem.
