# L10 · W2 — Napraw właściwą warstwę

**CORE: 20 min. Efekt:** mały diff i test regresji potwierdzonej luki. Wymagane: raport W1.

## Zrób

1. Wybierz jeden problem z dowodem, nie hipotetyczną listę wszystkiego. Odtwórz go na poprzednim commicie. Test ma najpierw nie przechodzić.
2. Przypisz warstwę naprawy: obcy rekord → auth/RLS; dowolny URL → allowlista i bezpieczny adapter; zmienione argumenty działania → związanie approval z payloadem; model bez dowodu → kontrakt i walidacja źródła.
3. Nie traktuj blacklisty słów „ignore/system prompt” jako granicy bezpieczeństwa. Polityka i uprawnienia są poza LLM. Nie umieszczaj sekretu w system prompcie z nadzieją, że filtr go ukryje.
4. Po zmianie powtórz atak i oba dozwolone zadania. Nie akceptuj naprawy przez odrzucenie każdej wiadomości lub ukrycie endpointu tylko w UI.
5. Zapisz przed/po, zmienione pliki, wynik testu, znane ograniczenia oraz sposób cofnięcia. Nie publikuj pełnych payloadów z prawdziwymi danymi.

## Polecenie do asystenta

```text
Odtwórz wskazany FAIL, dodaj test regresji i zaproponuj najmniejszą naprawę właściwej warstwy. Nie wyłączaj RLS/auth i nie przepisuj całej aplikacji. Po poprawce uruchom ten test oraz dwa normalne scenariusze. Pokaż diff i rzeczywiste wyniki, a pozostałe ryzyka zostaw jawnie otwarte.
```

## Odbiór

Stary kod odtwarza błąd; nowy blokuje konkretny skutek; normalne zadania nadal działają; test w repo chroni przed powrotem błędu. Filtr odpowiedzi może być dodatkową warstwą, ale nie zastępuje autoryzacji narzędzia.

**Ratunek:** usuń tylko niepotrzebne uprawnienie narzędzia i uzgodnij mniejszy zakres procesu, zamiast pozorować naprawę. **STRETCH:** test tego samego kontraktu na modelu fallback oraz po aktualizacji promptu.
