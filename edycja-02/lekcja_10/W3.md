# L10 · W3 — Budżet przed wywołaniem, nie po rachunku

**CORE: 20 min. Efekt:** limit równoległych zadań i prywatny panel. Wymagane: Auth, trwały magazyn i zliczanie usage.

## Zbuduj

1. Oddziel limity: liczba requestów, liczba aktywnych runów, tokens i wydatki. Wszystkie modele, kroki, retry, search, obrazy oraz embeddingi mają koszt; tokeny tekstu nie opisują wszystkiego.
2. Rezerwuj budżet atomowo PRZED wywołaniem na podstawie ustalonego maksymalnego zakresu. Po wyniku rozlicz użycie i zwolnij nadmiar. Niepewny status dostawcy nie uzasadnia natychmiastowego ponowienia ani automatycznego wyzerowania rezerwacji.
3. Magazyn współdzielony między instancjami; lokalna Map nie zabezpiecza serverless. Limit klucza OpenRouter u Laba jest niezależną ostatnią barierą, a nie zamiennikiem limitu użytkownika.
4. Dodaj /admin/security: liczba odrzuceń, błędy, koszt, niezakończone runy. Dostęp wyłącznie sprawdzaną na serwerze rolą admina. Nie pokazuj treści wszystkich prywatnych rozmów jako „monitoringu”.
5. Test offline: limit 2 aktywnych runów, 5 jednoczesnych żądań. Dokładnie maksymalnie 2 docierają do sztucznego adaptera; pozostałe są zatrzymane. Brak magazynu limitu → fail closed.

## Polecenie do asystenta

```text
Dodaj atomową rezerwację budżetu i limit współbieżności w trwałym magazynie. Nie używaj Map jako produkcyjnego limitera. Rejestruj usage ze wszystkich wywołań; cost_usd null gdy nieznany. Panel admin chroniony backendowo. Testuj równoległe żądania i awarię magazynu na adapterze bez kosztów.
```

## Odbiór

Współbieżność nie omija limitu; B nie widzi panelu; koszt nieznany nie jest 0; brak auth i brak limitera zatrzymują płatną operację; logi nie zawierają kluczy.

**Ratunek:** jeden limit równoległych runów plus limit klucza, pozostałe limity jawnie jako TODO. **STRETCH:** oddzielny budżet tenant/per-user oraz kontrolowany kill switch.

**Praca domowa L10:** trzy uzgodnione próby testerów, raport luk, poprawka i regresja. Bezpieczeństwo nie jest potwierdzane samą liczbą zablokowanych prób. Checkpoint L10.
