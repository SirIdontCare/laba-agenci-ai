# L06 · W3 — Odpowiedź 490, nie archiwalne 440

**CORE: 20 min. Efekt:** cytowane odpowiedzi i uczciwe „brak danych”. Wymagane: W1/W2.

## Zrób

1. Narzędzie searchKnowledge zwraca wyłącznie uprawnione źródła: source_id, document_id, version, fragment i lokalizację. Nie zwraca całej bazy „na wszelki wypadek”.
2. Model odpowiada, a aplikacja sprawdza, czy wskazane source_id pochodzą z bieżącego wyniku retrieval. Sam istniejący ID nie dowodzi, że cytat wspiera zdanie — sprawdź treść dowodu ręcznie w ćwiczeniu.
3. UI pokazuje pod odpowiedzią klikalny fragment i wersję. Bez dostępu do źródła nie otwiera treści. Odnośnik nie może omijać RLS.
4. Uruchom sześć `rag_tests`: netto Start 490; Enterprise brak; pierwsza odpowiedź nie oznacza naprawy; brutto nieznane bez VAT; B niedostępne; zmiana pakietu tylko szkic.
5. Dodaj siódmy test: fragment dokumentu zawiera instrukcję zmiany uprawnień. Nie wykonuj jej. Dla pustego retrieval zwracaj brak potwierdzenia; nie traktuj samego podobieństwa wektorów jako pewności odpowiedzi.

## Polecenie do asystenta

```text
Dodaj odpowiedzi ze źródłami i walidację identyfikatorów cytatów. Pokaż fragment, wersję i braki. Testy pobierania danych oddziel od oceny generacji. Zapisz listę source_id, które trafiły do modelu, oraz wyniki sześciu rag_tests. Nie używaj całej bazy po nieudanym wyszukiwaniu jako ukrytego fallbacku.
```

## Odbiór

Sześć prób ma udokumentowane wyniki; 490 jest z aktywnego cennika; 440 nie staje się aktualną ceną; B nigdy nie dociera do modelu; source_id nie da się wymyślić; brak VAT nie prowadzi do dopisania stawki. Pojedynczy PASS nie jest dowodem odporności na wszystkie halucynacje.

**Ratunek:** prześledź jeden przykład: pytanie → fragmenty → odpowiedź. **STRETCH:** pokaż osobno retrieval recall na oznaczonych źródłach i ocenę odpowiedzi; model oceniający jest pomocą, nie jedynym sędzią.

**Praca domowa L06:** trzy aktywne dokumenty, archiwum i próba obcego konta; dowody odpowiedzi i odmów. Checkpoint L06.
