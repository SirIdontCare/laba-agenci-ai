# L11 · W2 — Ile kosztuje poprawnie ukończona misja?

**CORE: 20 min. Efekt:** dashboard jakości i kosztu z prawdziwych rekordów. Wymagane: runs/usage oraz testy.

## Zrób

1. Zbierz stałą próbkę zadań: sukces, brak danych, błąd narzędzia i odmowa dostępu. Oznacz DEMO/LIVE i nie mieszaj sztucznego usage z rachunkiem.
2. Oblicz: liczba prób; poprawnie ukończone misje; needs_review; awarie; czas; koszty wszystkich prób. Kryterium poprawności pochodzi z testu procesu, nie samego status=200.
3. Koszt poprawnej misji = koszt wszystkich prób / liczba poprawnych misji. Gdy poprawnych jest 0, pokaż N/A. Gdy brakuje danych o kosztach, pokaż niepełny pomiar; nie sumuj null jako prawdziwego zera.
4. Włącz ręczny czas przygotowania i kontroli do porównania z pracą bez aplikacji. Szybszy model może tworzyć więcej poprawek. Profil quality porównuj z fast na tej samej próbie.
5. Ręcznie policz 3 wybrane runy i porównaj z dashboardem. Panel chroniony rolą admina. Cena katalogowa jest estymacją; rozliczenie provider może się różnić.

## Polecenie do asystenta

```text
Dodaj dashboard oparty na rzeczywistych runs i usage. Pokaż jakość, błędy, czas, koszt oraz kompletność danych. Nie nazywaj wszystkich odpowiedzi sukcesem. Koszt na poprawny wynik obejmuje koszt nieudanych prób. Obsłuż zero sukcesów i nieznany koszt. Dodaj test agregacji oraz autoryzacji panelu.
```

## Odbiór

Ręczny rachunek zgadza się z panelem; nieudane próby nie znikają; null nie udaje 0; zero sukcesów nie daje „0 zł za sukces”; model rzeczywiście użyty jest widoczny.

**Ratunek:** tabela runów i ręczny rachunek przed wykresami. **STRETCH:** alarm pogorszenia jakości po zmianie modelu i offline test regresji przed przełączeniem profilu.
