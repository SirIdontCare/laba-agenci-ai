# L03 · W1 — Wyszukiwanie to dopiero źródło, nie gotowa prawda

**CORE: 15 min. Efekt:** wynik wyszukiwania z metadanymi i odróżnienie narzędzia natywnego od własnego.

## Zbuduj

1. Włącz web search tylko dla profilu/przycisku, który go potrzebuje. OpenRouter udostępnia plugin `web`; opcje, silnik i koszt zależą od konfiguracji [OR-WEB]. Nie używaj starego `useSearchGrounding` providera Google.
2. Zapytaj o aktualny publiczny parametr techniczny, np. wymagania instalacji Next.js. Pokaż datę sprawdzenia i URL z `annotations/url_citation`, nie odtworzony z wyobraźni modelu.
3. Znormalizuj wynik do `{source_id,url,title,excerpt,checked_at}`. Linki renderuj wyłącznie jako http/https; treść jako tekst lub sanitizowany Markdown. Brak metadanych źródła → „Nie udało się potwierdzić”, nie wymyślony przypis.
4. Przy zwykłym pytaniu o prywatny cennik nie uruchamiaj publicznego search. To kwestia doboru danych, nie inteligencji modelu.
5. Pokaż, że plugin wyszukiwania jest usługą dostawcy, a `getOffer(plan)` będzie naszym narzędziem czytającym konkretne dane. Model może proponować wywołanie; backend je wykonuje.

## Polecenie do asystenta

```text
Dodaj serwerowy adapter web research przez OpenRouter. Plugin web włączaj jawnie, nie globalnie. Pokaż metadane cytatów, checked_at i kontrolowany brak źródeł. Nie pobieraj dowolnych URL otrzymanych od modelu. Testuj brak wyników, nieprawidłowy URL i zwykłe pytanie niewymagające internetu.
```

## Odbiór

Co najmniej jedno twierdzenie ręcznie porównano ze źródłem; pytanie bez potrzeby search nie generuje kosztu search; brak źródeł ma stan błędu/niepewności. Źródła nie nadają uprawnień aplikacji.

**Ratunek:** użyj zapisanego wyniku z etykietą REPLAY; nie udawaj aktualnego wyszukiwania. **STRETCH:** sprawdź dostępne server tools OpenRouter i porównaj z pluginem, ale nie zmieniaj ścieżki CORE w trakcie zajęć.
