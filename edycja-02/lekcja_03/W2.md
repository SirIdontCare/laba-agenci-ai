# L03 · W2 — Obraz na wejściu, grafika na wyjściu

**CORE: 20 min. Efekt:** dwa różne typy narzędzi. Wymagane: profile vision i image oraz zaakceptowany koszt.

## Zbuduj

1. Utwórz sam prostą planszę testową z napisem „Start 490 PLN netto / 3 konta” i zrób screenshot. To własny materiał; nie zdjęcie klienta. Użyj modelu z `image` w input_modalities.
2. Upload PNG/JPEG/WebP: sprawdzaj MIME i rzeczywisty typ na serwerze, maksymalnie 2 MB na start. Nie wysyłaj dowolnego zewnętrznego URL. Binarne dane/base64 zwiększają payload — limit hostingu także obowiązuje.
3. Poproś o odczyt ceny, kont i brakujących warunków. Weryfikuj liczby ręcznie. Nieczytelny fragment ma dać brak danych, nie pewną odpowiedź.
4. Oddzielny przycisk generacji używa modelu z `image` w output_modalities. Przez udokumentowane API OpenRouter ustaw odpowiednie modalities i pokaż zwrócony plik [OR-IMAGE]. Nie zakładaj, że model tekstowy generuje obraz lub że grafika jest darmowa.
5. Przetestuj brak obrazu w odpowiedzi, odmowę i za duży plik. Wynik graficzny jest szkicem do kontroli: tekst, prawa do materiałów i zgodność z briefem nadal sprawdza człowiek.

## Polecenie do asystenta

```text
Dodaj analizę własnego obrazu testowego oraz osobną generację grafiki przez OpenRouter. Profile dobierz na serwerze według modalności. Klucz pozostaje serwerowy. Dodaj walidację pliku, limit payloadu i obsługę braku obrazu/odmowy. Nie mieszaj kontraktów vision i image generation.
```

## Odbiór

Odczyt wskazuje 490 i 3 albo uczciwy brak; plik graficzny rzeczywiście istnieje; nieobsługiwany/za duży plik jest odrzucony przed wywołaniem; brak modelu image nie wywołuje innego kosztownego modelu po cichu.

**Ratunek:** dostępny tylko vision → ukończ analizę, generację oznacz NOT RUN i dokończ po przyznaniu profilu. **STRETCH:** porównaj obraz i OCR/tekst na pięciu fragmentach, zamiast zakładać idealny odczyt.
